## 1. Goal

A Cyberpunk 2077 **ripperdoc bench** at `/loadout` where the reproduced-research artifacts ("zords") are **cyberware implants** and the agent harness is the **body** you plug them into. A visitor browses implants by body system, equips a loadout, watches **real harness gauges** move, sees **friction between implants** surfaced honestly, and exports a **shareable build code / URL**.

The page is a **playful showcase and instrument**, not a live activation tool. It respects megazord's inert-until-verified discipline: it produces a *proposed build*, never wires anything.

**The thesis:** it is a harness-metrics dashboard disguised as a ripperdoc build screen. Equipping an implant makes a *true statement* about whether a harness config is coherent — what it costs in context, which capabilities it covers, and where implants fight.

## 2. Scope & non-goals

**In scope:** the `/loadout` page, its data model, the shared `zords.json` data source, and the megazord-side export tooling that feeds it.

**Out of scope (separate specs, per the agreed decomposition):**
- **Dynamic org README** — consumes the same `zords.json`; its own spec.
- **Landing-page terminal/easter-egg polish** — its own spec (landing-page-design skill). *Page-level* easter eggs local to `/loadout` (§11) are in scope here; site-wide ones are not.

**YAGNI:** no accounts, no persistence beyond the URL, no real plugin installation, no live megazord wiring, no editing zords from the site.

## 3. The isomorphism (grounded)

The metaphor is a near-exact map onto data that already exists in the megazord manifests. This table is the spec's backbone.

| Cyberpunk 2077 mechanic | Real harness metric | Data source |
|---|---|---|
| Cyberware **Capacity** (equip budget) | **CONTEXT LOAD** — tokens the implant adds to live context | **Measured** — token count of the component's public payload (§4) |
| Body-system **slot** | `layer` + `hook_point` | manifest |
| Arm/OS **mutual exclusivity** (one only) | **single-active-per-layer** rule | HIERARCHY |
| Implant **stat bonuses** | **BENEFIT axes** = `improves:` vocabulary | manifest `improves:` + real reproduced headline |
| Over-capacity → **cyberpsychosis** | **DRIFT / CONTAMINATION** risk | **Derived** from `isolation` write-slice overlap |
| Incompatible implants | **conflict register** (funes⟷HLER) | manifest `isolation` + HIERARCHY conflicts |
| **Set bonuses** | **stacks** (same `improves:` across layers) | HIERARCHY stacks |
| Quality **tier** (Common→Legendary) | **provenance** — `status` + test count + FAITHFUL grade | registry `status` + repo test counts |
| **Attribute requirement** to equip | `requires_target_fit` / dependencies | manifest |

**Honesty stance (no mocks):**
- **COST axis is measured** — `context_cost_tokens`, `tests`, are real counts of real artifacts.
- **BENEFIT axis is *rated*, not measured** — `improves:` targets rendered as buff lines. Intensity is a transparent ordinal (primary target = `++ STRONG`, secondary = `+ MODERATE`), plus the zord's **real reproduced headline** as grounding text. Every benefit line is labeled `rated`; every cost line `measured`; drift `derived`. No fabricated precise numbers.

## 4. Data model & source of truth

megazord stays canonical. The site consumes a **curated snapshot**, `src/data/zords.json`, generated by a new megazord exporter.

### 4.1 megazord side (`~/code/megazord`)
- Add an optional **`cyberware:` overlay** — one YAML file `components/cyberware-overlay.yaml` keyed by zord name — holding the flavor the manifests don't have: `manufacturer`, `flavor` (one-line lore), `headline` (the real reproduced result string), and any `tier_override`. Kept separate so manifests stay clean.
- Extend `bin/megazord` with **`export-json`**: merges each manifest (`name, paper, layer, hook_point, method, improves, isolation, status`) + the overlay + a computed `context_cost_tokens` (token count of `interface` + `flavor` + manifest body — a real measurement of the text that would load into context) → writes `zords.json`. Also emits the derived `conflicts` and `stacks` from HIERARCHY.
- **Full-publish** (David's call): the export includes `isolation` slices, conflicts, arXiv ids, layer architecture — no curation/redaction.

### 4.2 site side (`~/code/dinnaga`)
- `src/data/zords.json` — the committed snapshot (vendored; the site is public and cannot reach private megazord at build time).
- **Sync is a documented manual step** (megazord `export-json` → copy into the site). A schema-validation test (§13) guards shape/consistency; it cannot reach megazord in public CI, so freshness is a human step, not CI-enforced.

## 8. The friction engine (pure, TDD)

`src/lib/friction.ts` — pure functions over the equipped set. This is the analytically useful core.

**Inputs:** equipped `Zord[]`, plus `conflicts` and `stacks` from `zords.json`.

**Per unordered pair (a, b):**
1. **Slot collision** — `a.layer === b.layer` in a `single` slot. Structurally prevented by the UI (one per slot); kept as a guard/invariant.
2. **Write overlap (contamination)** — `writes(a) ∩ writes(b) ≠ ∅` → contamination weight `+= |overlap|`. Feeds DRIFT.
3. **Read-after-write hazard** — `reads(a) ∩ writes(b) ≠ ∅` → ordering/dependency flag (fragility unless it is a registered stack).
4. **Registered conflict** — `(a,b) ∈ conflicts` → named `✕ CONFLICT` with its documented `resolution`; **resolvable** (user can "APPLY" the isolation mask, which zeroes its DRIFT contribution).
5. **Synergy** — `improves(a) ∩ improves(b) ≠ ∅` and different layer → `⊕ SET BONUS` on the shared target(s); named if it matches a `stacks` entry.

**Aggregates:**
- `contextLoad = Σ context_cost_tokens` vs `capacity.context_budget_tokens`.
- `drift = Σ contamination weights (1 per overlapping write-slice) + 2 per unresolved registered conflict`, clamped to `[0, drift_max]`. Resolving a conflict zeroes its contribution.
- `coverage` = union of `improves:` across the loadout (which benefit axes are covered).
- Outputs a typed `FrictionReport { synergies[], conflicts[], hazards[], drift, contextLoad, coverage }`.

**Cyberpsychosis:** `drift ≥ drift_max` → the HUD flips to a glitchy MU-TH-UR/HAL "HARNESS INTEGRITY COMPROMISED" state (§11). Never blocks export; stamps the build **UNSTABLE**.

## 10. URL state & build code

- **State lives entirely in the URL** — `?b=L1genome.L3funes.L4hler` (`<slotId><zordName>` dot-joined; Subdermal allows multiple). Loading a shared link restores the build. No storage.
- `src/lib/buildcode.ts` (pure, TDD): `encode(loadout) → param`, `decode(param) → loadout` (round-trip tested), `shortCode(loadout)` → `GNM·FNS·HLR` display code, `autoName(loadout)` → derived name from the dominant `improves:` axis / a matched `stacks` name.
- **SHARE** copies the full URL; **COPY** copies the short build code + name.
- Unknown zord id / bad param → ignored gracefully with a "couldn't parse part of that build" notice.

## 13. Testing strategy (TDD; unit + integration + e2e)

- **Unit (pure):** `friction.ts` — every rule (write-overlap, hazard, registered conflict + resolution, synergy, drift clamp, cyberpsychosis threshold, coverage). `buildcode.ts` — encode/decode round-trip, short code, auto-name, malformed input.
- **Unit (data):** `zords.json` **schema-validation test** — every zord has a valid `slot`, `tier` derivable from a known `status`, `isolation` present; conflicts/stacks reference existing zords; no dangling refs. (Shape guard; not megazord-freshness.)
- **Integration (RTL):** `BodyNav` selection → candidate list; `ImplantCard` click → `ImplantModal`; equip/unequip updates HUD + FrictionPanel; conflict `[RESOLVE]` lowers drift.
- **E2E (Playwright):** land → equip genome + funes + hler → see conflict → resolve → SHARE → reload the shared URL → build restored. Reduced-motion path.
- Pristine output; lint + typecheck clean; real data (the actual `zords.json`), no mocks.

## 14. Edge cases

Empty loadout ("UNPOWERED") · all single-slots full · Subdermal with several diagnostics · unresolved-conflict export (allowed, stamped **UNSTABLE BUILD**) · unknown zord id in shared URL (graceful) · reduced-motion (no glitch/boot animation) · a slot with only one candidate · a slot with zero candidates (Operating System today).

## 15. Decisions resolved (David)

- **Export = shareable build code / URL** (showcase, state in URL; no live wiring).
- **Mechanic = constrained build; capacity = measured CONTEXT LOAD; every equip moves real gauges.**
- **Stats = fun, Cyberpunk conventions; benefit = rated buffs (signify what's affected), cost + friction = grounded/useful.**
- **Data boundary = FULL PUBLISH** (architecture, isolation, conflicts, arXiv ids all public).
- **Route = `/loadout`.**

## 16. Success criteria

- A visitor can browse all built zords as implants by body system, open a stat modal, equip a coherent loadout, and see context load + drift + synergies + conflicts update live.
- Conflicts and contamination are surfaced **from the real `isolation` masks** — the page genuinely tells you which implants fight.
- A build is shareable via URL and restores exactly on reload.
- All stats are honestly labeled measured / rated / derived; nothing fabricated.
- megazord remains source of truth; the site renders a vendored snapshot; nothing is wired live.
