Building LLM Eval Harnesses: Dataset Vetting & Judge Prompts

The operator had Claude grade sampled benchmark rows (SQuAD, GLUE) for well-formedness and score response directness — core building blocks of an LLM-as-judge eval harness.

  • LLM-as-judge is now standard practice, but the 2026 production pattern is hybrid: metrics where measurable, LLM judges for reasoning-heavy calls, and human review for the disputed tail (roughly 1-5% of samples).
  • Judge quality is task-specific, not universal — the right move is running a few candidate judge models against a small human-labeled set and checking agreement before trusting one at scale.
  • Effective golden/eval datasets tend to be small (200-500 examples) and built from real observed failures rather than synthetic data.

Claude Code Skill Ecosystem & Workflow Design

The operator asked for an analysis reconciling three overlapping Claude Code skill stacks into one coherent programming workflow, including where GitHub Actions could plug in.

  • Skills are filesystem-based (~/.claude/skills/ or project .claude/skills/) and load into context only when invoked, not ahead of time — so overlapping skill stacks can coexist without bloating every session.
  • A skill defines *what* to do; a subagent (its own context window, tools, and permissions) defines *who* does it — the distinction matters when merging multiple skill stacks so they compose instead of collide.
  • Claude Code's official GitHub Action can be triggered via an @claude PR/issue comment or on any repo event, making it a natural place to wire in a settled multi-skill workflow for review or automation.

Multi-Session / Multi-Agent Claude Orchestration

The operator ran a fleet of parallel research teammate sessions mining reference sites, surfacing idle/failure notifications and a case worth flagging: a peer session's message is not the same as user authorization.

  • Claude Code's Agent Teams feature (distinct from plain subagents) lets multiple full Claude Code instances share a task list, claim work, and message each other directly.
  • Subagents, by contrast, only report results back to the parent session and never talk to each other peer-to-peer — the right choice depends on whether the work needs cross-agent negotiation or just fan-out/fan-in.
  • Agent Teams is still experimental and opt-in (CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1); a teammate session cannot grant escalated permissions or launder a denied action through another session.

Personal Knowledge Base Tooling (Obsidian-backed vault)

The operator pushed a git-backed Obsidian vault to GitHub, then chased down why changes weren't showing up on a phone, and asked for a CLI plus lint/distill passes.

  • The community Obsidian Git plugin runs on isomorphic-git under the hood on mobile, and its own maintainers say it's unstable there — no SSH auth support and memory-driven repo-size limits — which explains desktop-commits-but-phone-shows-nothing symptoms.
  • A dedicated mobile-sync plugin is a better fit than Obsidian Git's mobile leg for reliably reaching a vault from a phone.

Headless Reporting Agents (nightly/weekly automation)

The operator retired a risky nightly auto-commit job in favor of a read-only nightly state-of-the-world report, added a weekly session-reflection pass, and wired a weekly run-log page — all driven by headless Claude Code runs.

  • Headless mode (`claude -p`) runs Claude Code non-interactively from shell scripts, cron, or CI — reading a prompt directly and writing structured output via `--output-format json`.
  • `--allowedTools` and `--permission-mode` let an unattended run proceed without blocking on an approval prompt, which is what makes a genuinely hands-off nightly/weekly job possible.
  • The documented pattern is chaining headless runs as nodes in a pipeline — one run's JSON output feeding the next — which matches the nightly-facts → nightly-report → weekly-digest chain the operator built this week.

Tailscale Remote Access & Persistent Device Auth

The operator hit repeated re-auth prompts reaching a tailnet device from different browsers and wanted access to persist going forward.

  • Long-term device authorization actually rides on the node key created at login, not the original auth method — node keys auto-expire every 180 days by default regardless of how the device first joined.
  • Pre-approved or tagged auth keys let a device skip interactive re-authorization entirely — the mechanism to reach for when a device should 'just stay in' instead of re-prompting per browser or session.
  • Auth-key secrets are sensitive and worth deliberately rotating/expiring, which is a good reason to set a reminder rather than leaving a pasted key live indefinitely.

Web Design Research → Reusable Skill Distillation

The operator wants to mine the original reference sites behind an earlier portfolio exercise for CSS and visual-design techniques, then fold the findings into a growing, reusable design skill.

  • Design tokens — layered as primitive, semantic, and component values — are the standard vocabulary for capturing a site's visual system in a reusable, diffable form rather than as free-text notes.
